# Doctor Eleks Automation

Локальна Windows-програма для описаного робочого процесу реабілітації.

## Запуск

1. Встановити Python 3.11+.
2. Розпакувати ZIP у звичайну локальну папку.
3. Запустити `run.bat`.
4. Не закривати консольне вікно, поки програма потрібна.
5. UI автоматично відкриється у браузері на `http://127.0.0.1:8787` або найближчому вільному порту.

При першому запуску `run.bat` створює `.venv` і встановлює залежності.

## Що вже реалізовано

### Процедури — перші для тестування

- `Внести процедури`
  - читає вкладку ЕТ/ФТ;
  - знаходить одного пацієнта та конкретного спеціаліста;
  - читає код призначення з колонки R;
  - очікує 14 процедур для AR2;
  - запускає/підключає керований Edge/Chrome;
  - знаходить пацієнта і направлення;
  - створює процедури по 30 хв у час із графіка;
  - після успішного `Підписати пізніше` робить відповідну клітинку Excel жирною;
  - зберігає progress, щоб не повторювати вже завершені клітинки.

- `Пакетно підписати процедури`
  - відкриває пакетне опрацювання;
  - тип МЗ `Процедура`;
  - вибирає рядки пацієнта;
  - доходить до КЕП і зупиняється для ручного підпису.

### IMPORTANT_000

Внутрішній ID `important_000` незмінний, навіть якщо користувач перейменує функцію.

- `IMPORTANT_000` — виконує обидві перевірки одним читанням вкладок.
- `Перевірити ФРМ → ЕТ/ФТ`.
- `Перевірити перетини ЕТ/ФТ`.
- `Кол-во процедур` — бере унікальних пацієнтів зі стовпця C вкладки `Розподіл АР2`,
  якщо в їхньому рядку колонки `Статус ПЛ` вказано `є + направлення`,
  перевіряє 14 днів із записами та рівно 2 процедури на день сумарно на `ЕТФТ`
  і `ПСИХЛого`. На `ПСИХЛого` допускається щонайбільше одна процедура
  **в один день**; за весь курс їх може бути більше. У результаті показує
  дату, кількість, клітинки, час, спеціалістів і підсумок по пацієнту.
  Для пацієнтів вкладки `25 пакет` із таким самим статусом ПЛ перевіряє щонайменше
  21 процедуру в кожному місяці перевірки та рівно одну процедуру на день; різні спеціалісти
  допустимі. Якщо пацієнт є на обох вкладках,
  діє правило `25 пакет`. Записи з позначкою `25` у графіку зіставляються також
  за прізвищем та ім’ям, якщо на вкладці `25 пакет` цей збіг однозначний.
  Можна вибрати місяць: тоді підраховуються лише дати цього місяця,
  а вимога 14 днів для АР2 не застосовується до частини курсу. Для `25 пакет`
  мінімум 21 процедури застосовується і до вибраного місяця; без вибору місяця — окремо до кожного місяця з графіка або колонки `Міс`.

Перевірки:
- ідентифікують пацієнта тільки за нормалізованим ПІБ;
- не використовують дату народження;
- працюють з 30-хвилинною сіткою;
- визначають 60 хв через порожню нижню клітинку того самого фактичного кольору;
- біла клітинка не продовжує запис;
- не використовують fuzzy matching;
- показують координати та інтервали;
- окремо показують попередження структури Excel;
- пишуть порушення в журнал;
- overlap-перевірка використовує індексацію + сортування + sweep-line, а не повний попарний scan таблиці.

### Інші функції робочого процесу

- перенесення даних із таблиці координаторів у Графік 1;
- пошук висновку невролога у Doctor Eleks Desktop;
- підготовка матеріалу для діагнозів і запис підтверджених кодів у N;
- діагностична перша взаємодія;
- направлення на нестаціонарну реабілітацію;
- реабілітаційна перша взаємодія;
- звірка діагнозів із N, ролей, звіту 96 0 22 00 та базових МКФ;
- повторне направлення після реабілітації;
- чернетка плану лікування без заявки;
- подання плану після статусу `Кидайте`;
- OTP та первинні призначення;
- 420 хв / 1 місяць / `Підтримка стану пацієнта` для AR2;
- направлення з первинних призначень без взяття в роботу;
- оновлення O/P/Q у Графік 1 у відповідних workflow.

## Важливо про КЕП та OTP

Програма не зберігає пароль КЕП.

На точці КЕП workflow зупиняється. Користувач підписує запис і повторно запускає ту саму функцію для продовження/підтвердження.

OTP також не потрапляє в audit-log. Для первинних призначень реалізовано:
- 4 цифри;
- TTL 10 хвилин;
- не більше двох автоматичних запитів коду в одному локальному workflow.

## Налаштування

В UI → `Налаштування`:

- `Графік 1`;
- таблиця координаторів;
- Doctor Eleks Desktop EXE;
- URL Doctor Eleks/eHealth;
- Edge/Chrome EXE — зазвичай можна не задавати;
- назви вкладок ФРМ, ЕТ/ФТ, Розподіл AR2;
- `safe_mode`;
- словник спеціалістів.

Приклад:

```json
{
  "Халай Тимофій": {
    "type": "ET",
    "profile_text": "Халай Тимофій"
  }
}
```

`profile_text` дає можливість процедурному workflow перевірити, що відкритий правильний профіль.

## Safe mode

Початково `safe_mode = true`.

Він дозволяє заповнити форму, але не натискає фінальні кнопки підпису. Для контрольованого тесту це бажано.

Коли селектори Doctor Eleks на конкретному середовищі перевірені, safe mode можна вимкнути у `Налаштуваннях`.

## UI

Можна:
- перейменувати будь-яку функцію;
- додати власну примітку до 300 символів;
- створювати групи;
- перейменовувати групи;
- перетягувати функції drag-and-drop між групами й вгору/вниз.

Змінюється тільки користувацьке представлення. Стабільні системні ID функцій не змінюються.

## Логи

- `logs/app.log` — компактний технічний журнал;
- `logs/audit.jsonl` — структурований audit trail;
- `logs/browser-actions.jsonl` — браузерні дії;
- `logs/errors/` — screenshot + HTML сторінки при помилках автоматизації;
- SQLite `data/app.db` — workflow state, audit і результати перевірок.

Не логуються:
- пароль КЕП;
- OTP;
- повний текст медичного документа в audit trail.

## Excel

Перед змінами Excel створюється резервна копія в `data/backups/`.

Для процедур клітинка графіка виділяється жирним тільки після успішного `Підписати пізніше`.

## Browser automation

Програма запускає встановлений Edge/Chrome з окремим профілем:

`runtime/browser_profile`

і локальним remote-debugging port.

Це дозволяє:
- браузеру залишатися відкритим;
- користувачу вручну пройти КЕП/авторизацію;
- наступному запуску функції знову підключитися до тієї ж сесії.

## Doctor Eleks selectors

Тексти та semantic selectors зібрані в `config/selectors.json`.

Якщо у вашій інсталяції назва/DOM елемента відрізняється, змінюється тільки цей JSON або відповідний адаптер, а не весь workflow.

Детальніше: `docs/SELECTOR_GUIDE.md`.
